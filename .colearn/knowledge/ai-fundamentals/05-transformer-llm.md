# 第5章：Transformer 与大语言模型

## 从 RNN 到 Transformer

RNN 的问题：
- 顺序处理，不能并行
- 长序列时梯度消失，记不住远处的信息
- LSTM/GRU 缓解但没根治

Transformer 的解决方案：**完全抛弃循环结构，用注意力机制直接建模任意位置之间的关系。**

## 自注意力机制（Self-Attention）

核心思想：对于序列中的每个位置，计算它与所有其他位置的相关性，然后加权求和。

```
输入："我 喜欢 机器 学习"

对于"学习"这个词：
  - 与"我"的相关性：0.1
  - 与"喜欢"的相关性：0.2
  - 与"机器"的相关性：0.6  ← 最相关
  - 与"学习"自身：0.1

输出 = 0.1×"我" + 0.2×"喜欢" + 0.6×"机器" + 0.1×"学习"
```

数学公式：Attention(Q, K, V) = softmax(QKᵀ/√d) × V

- Q（Query）：我在找什么
- K（Key）：我有什么可以被找到
- V（Value）：找到后返回什么

## Transformer 架构

```
输入 → Embedding + 位置编码
     → [多头注意力 → Add&Norm → FFN → Add&Norm] × N层
     → 输出
```

关键组件：
- **多头注意力**：多个注意力头并行，捕捉不同类型的关系
- **位置编码**：告诉模型词的顺序（因为注意力本身不感知位置）
- **残差连接 + LayerNorm**：稳定训练
- **前馈网络（FFN）**：两层全连接，增加非线性

## 大语言模型（LLM）

本质：超大规模的 Transformer，在海量文本上训练。

### 训练方式

1. **预训练**：在互联网文本上做"下一个词预测"
   - 输入："今天天气"
   - 目标：预测下一个词是"很好"

2. **指令微调（SFT）**：用人工标注的问答对微调
3. **RLHF**：用人类偏好反馈进一步对齐

### 规模定律（Scaling Laws）

模型性能随三个因素提升：
- 参数量（模型大小）
- 数据量（训练数据）
- 计算量（训练时间）

| 模型 | 参数量 | 训练数据 |
|------|--------|----------|
| GPT-2 | 1.5B | 40GB 文本 |
| GPT-3 | 175B | 570GB 文本 |
| GPT-4 | ~1.8T（推测） | ~13T tokens |
| DeepSeek-V3 | 671B（MoE） | 14.8T tokens |

### 涌现能力

当模型足够大时，突然出现小模型没有的能力：
- 思维链推理（Chain-of-Thought）
- 少样本学习（Few-shot Learning）
- 代码生成
- 数学推理

## 关键概念

| 概念 | 含义 |
|------|------|
| Token | 模型处理的最小单位（大约 0.75 个英文单词或 0.5 个中文字） |
| Context Window | 模型一次能处理的最大 token 数 |
| Temperature | 控制输出随机性（0=确定性，1=创造性） |
| Prompt | 给模型的输入指令 |
| Fine-tuning | 在特定任务数据上继续训练 |
| RAG | 检索增强生成，让模型引用外部知识 |
